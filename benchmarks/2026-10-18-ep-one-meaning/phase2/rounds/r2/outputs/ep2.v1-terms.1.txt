# docs-plan.md

## Principle
Each fact gets one canonical home. Every other copy is deleted or replaced with a bare path, not a retelling. History lives in git only.

## Decisions

### 1. Local setup steps
- **Canonical:** `README.md`, in a "Setup" section.
- **CONTRIBUTING.md:** delete its copy of the steps. Replace it with one line pointing to `README.md#setup`, with no restated content.
- **Content of the canonical copy:** use the README version (`npm run dev`, copy `.env.example`). The CONTRIBUTING version is stale. `npm start` was retired in favor of `npm run dev`, and the hand-created `.env` duplicates what `.env.example` already defines.
- **Open item to verify before merging:** `npm install` (README) vs `npm ci` (CONTRIBUTING). If a lockfile is committed, `npm ci` is usually the better instruction. Check `package-lock.json` and pick one. This is a content decision, not a duplication issue.
- **Underlying sources:** the `dev` script is defined in `package.json`, and env var names are defined in `.env.example`. The README refers to them and does not enumerate them.

### 2. API timeout (30s vs 45s)
- **Canonical:** the constant in `src/http/client.js`. It is the only place that decides the behavior, so it is the only place that can be right.
- **README.md:** delete the "30 seconds" sentence.
- **CONTRIBUTING.md:** delete the "45 seconds" sentence.
- **Do not pick a winner between 30 and 45.** Neither number is authoritative, and one of them is wrong today. If a doc must mention timeouts, it says "see `src/http/client.js`" with no number.
- **Action:** add a one-line comment above the constant saying it is the source of truth for the timeout.

### 3. Support email
- **Canonical:** `README.md`. It appears once, so there is no duplication.
- **CONTRIBUTING.md:** if it needs a contact, link to the README and don't copy the address.

### 4. `recalcTotals()` rule
- **Canonical:** a header comment at the top of `src/billing.js`: "After any mutation to line items, call `recalcTotals()`."
- **CLAUDE.md:** remove the rule. It applies to one file only, so it belongs in that file, where it loads when the file is touched. An always-loaded file shouldn't carry it.
- **Better, optional follow-up:** if the mutators can call `recalcTotals()` internally, the rule can be removed entirely and the comment is no longer needed. Removing the step beats documenting it.

### 5. "Lessons learned" section in CLAUDE.md
- **Canonical for history:** git log and blame.
- **Action:** delete the whole section. Do not move it to an ADR, CHANGELOG, wiki page, or new history file, and do not shorten it into another document.
- **Per entry:**
  - "2025-11: switched from `npm start` to `npm run dev` after the port clash": delete. The current state, `npm run dev`, is already stated in README Setup.
  - "2026-01: renamed the export module…": delete. The current module name is in the code.
  - Any other entry: if it implies a rule that is still true, state that rule alone, without the date or story, in the single file that owns it. Otherwise delete it.
