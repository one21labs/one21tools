### DEFECT 1 — `<<WORD` inside quotes truncates the real command (bypass)

**Input:** `echo "use <<EOF to start" && git reset --hard`  
**Observed:** `strip_heredocs` returns `echo "use `; `git_calls` → `[]` → **ALLOW**. Real shell still runs the reset.

**Why:** `HEREDOC.search` is quote-blind. On no following newline it returns `text[:m.start()]`, dropping everything after the false match — including a chained destructive git.

**Smallest fix:** Only treat `<<` as a heredoc when it is an unquoted redirection operator (tokenize first; or require `<<` not inside `'`/`"` / and not preceded by non-separator code). `not json: see git reset --hard docs`  
with project dirty  

**Observed:** DENY.  
`command_of` returns raw text + `parsed=False`; `decide` splits on `\bgit\b` and runs `git_calls` on each tail. No tool_name gate helps (`tool_of` → `""`, and `if tool and tool != "Bash"` is false).  

This is **over-denial** under broken/truncated stdin, not a clean agent bypass of valid PreToolUse JSON (Claude Code still sends real JSON for tool calls). **Smallest fix:** Fail-closed should only scan when the blob looks like a Bash tool payload (e.g. contains `tool_input` / `"command"`), **or** require that a reconstructed call’s tokens form a plausible `git <verb> …` with the verb in a deny-list — and never deny on free prose without `tool_name`/`command` structure. ### 4. `check-gate-tests` Python floor `/def\s+test/` — false positive: non-cases that merely start with `test`

**Widening past the runner rule.** unittest’s prefix is method names on `TestCase` starting with `test`. The floor accepts any line-start `def test…`, including free functions CI never runs (`python3 file` → exit 0).

**Input** (`readFile` body for a sibling `*_test.py` that gates.yml executes):
```python
def testing_helper():
    return 1
```
Also: `def testable(): pass`, `def testData(): return {}`.

`findMissingTests` → no finding. `python3 that_file.py` → exit 0, zero assertions.

Old `/def\s+test_/` rejected `testing_helper` / `testable` / `testData`.

**Smallest fix:** require a real case shape, e.g.  
`/^[ \t]*(async\s+)?def\s+test(?![A-Za-z0-9_]*ing)[A-Za-z0-9_]*\s*\(/m` is still weak; better:  
`/^[ \t]*(async\s+)?def\s+test[A-Za-z0-9_]*\s*\(/m` **and** either a `unittest.TestCase` subclass in the file or `unittest.main`, **or** stick to

Minimal practical pattern for this repo’s runners:
```js
/^[ \t]*(async\s+)?def\s+test(_|[A-Z])\w*\s*\(/m
```
(`test_…` or `testX…`, not `testing…` / `testable…`).
