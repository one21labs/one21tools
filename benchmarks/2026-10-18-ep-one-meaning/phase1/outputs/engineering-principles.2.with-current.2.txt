# docs-plan.md

Each fact gets one canonical home. Every other copy is deleted or becomes a bare pointer with no restated content.

## 1. Local setup steps
- **Canonical:** `README.md`, in a "Setup" section.
- **README.md:** keep, but check each step against `package.json`.
- **CONTRIBUTING.md:** delete its copy of the steps. Replace it with one line: "Local setup: see README.md#setup".
- **CLAUDE.md:** do not copy the steps there. Point to README only if the agent needs it.
- **Which copy is right:** the two copies contradict each other.
  - The README version (`npm run dev`, copy `.env.example`) is current. The CLAUDE.md draft says `npm start` was replaced by `npm run dev`, so the CONTRIBUTING version is the stale one.
  - Check one step before deleting: `npm install` (README) vs `npm ci` (CONTRIBUTING). Both work, but `npm ci` is stricter and needs a lockfile. Keep whichever the team wants contributors to run, and write it once.
- **Env variables:** `.env.example` is the single source for which variables exist. Docs say "copy `.env.example`" and never list variables.

## 2. API timeout
- **Canonical:** the constant in `src/http/client.js`. 30s and 45s are both unverified until someone reads that constant.
- **README.md and CONTRIBUTING.md:** delete the number from both, since a number in prose will drift again.
  - If readers need to know it, write "see the timeout constant in `src/http/client.js`" using the constant's name and path only.
  - Do not restate the value.
- **Contradiction:** it is resolved by deletion, not by choosing 30 or 45. Neither doc is trusted over the code.

## 3. Support email
- **Canonical:** `README.md`. It appears only there today, so there is nothing to merge.
- **Check:** grep `CONTRIBUTING.md` and `CLAUDE.md` for the address, and replace any copy with a pointer to the README.

## 4. "In `src/billing.js`, always call `recalcTotals()` after any mutation to line items"
- **Canonical:** a header comment at the top of `src/billing.js`, next to the code it constrains.
- **CLAUDE.md:** delete the rule. It applies to one file only, so it belongs in a place that loads only when that file is touched. Keeping it in CLAUDE.md would load it on every task for no benefit.
- **Better still, optional:** make the mutators call `recalcTotals()` themselves, or make totals derived on read. That removes the rule instead of documenting it. If that change isn't worth the effort, keep the comment.

## 5. "Lessons learned" section in CLAUDE.md
- **Canonical:** git history. It already holds the backstory.
- **CLAUDE.md:** delete the whole section. Do not move or condense it into a CHANGELOG, an ADR, a comment or a new history file.
- **Current-truth fragments:**
  - "Use `npm run dev`": already in README setup, so nothing to add.
  - "Port clash": if the current port constraint still matters, state it as a present-tense fact in the one place that defines the port (`.env.example` or the config file). Do not mention the incident.
  - "Renamed the export module": nothing to keep. The current name is in the code.
