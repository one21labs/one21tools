## 1. Setup steps (duplicated and contradictory)

- **Canonical:** `README.md`. It is the first file a new person reads, and it is the better-maintained copy.
  - The CONTRIBUTING copy has drifted. It says `npm start`, which the history in `CLAUDE.md` says was replaced by `npm run dev`.
  - It also says to create `.env` by hand, although `.env.example` exists to be copied.
- **`CONTRIBUTING.md`:** delete the setup steps. Replace them with one line that points to the README Setup section, with no restated commands.
- **Check before finalizing:** `npm install` (README) and `npm ci` (CONTRIBUTING) disagree.
  - If `package-lock.json` is committed, use `npm ci` in the README. It is reproducible.
  - If it isn't, keep `npm install`.
  - Confirm that `npm run dev` exists in `package.json`.
  - Make this a single edit in the README only.

## 2. API timeout (contradictory: 30s vs 45s)

- **Canonical:** the constant in `src/http/client.js`. The code is what actually runs.
- **`README.md` and `CONTRIBUTING.md`:** delete the sentence from both. Neither 30 nor 45 is trusted, and any number written in prose will drift again.
- If readers need to know where it is set, a reference may name only the file and constant (for example, "see the timeout constant in `src/http/client.js`"). It must not restate the value.
- Optionally, tell me the actual value afterwards so I can check the code against what readers have been told.

## 3. Support email (single copy, no action)

- **Canonical:** `README.md`. It appears nowhere else.
- **Rule:** don't add it to CONTRIBUTING or CLAUDE.md. Link to the README if needed.

## 4. `recalcTotals()` rule (misplaced)

- **Canonical:** a header comment at the top of `src/billing.js`: "After any mutation to line items, call `recalcTotals()`."
- **Reason:** the rule matters only in that file. A source header loads exactly when someone edits it. `CLAUDE.md` loads on every task and pays for a rule that is irrelevant to nearly all of them.
- **`CLAUDE.md`:** delete the rule. Don't add a pointer.

## 5. "Lessons learned" section (history in docs)

- **Canonical:** git history owns "what happened and when".
- **`CLAUDE.md`:** delete the whole section. Don't move it to a CHANGELOG, an ADR, a comment, or a new history file. Retelling it elsewhere just creates another copy to maintain.
- **Entries:**
  - **"2025-11: switched from npm start to npm run dev":** the current-state half, "use `npm run dev`", already lives in the README Setup section (item 1). Delete the rest.
  - **"2026-01: renamed the export module…":** delete it. The current module name is in the code.
  - **Port clash:** this is the only entry that might describe a live hazard. If it still happens, add one present-tense line to README troubleshooting, for example "Port X in use: do Y". It must contain no dates or narrative. If it no longer happens, add nothing.

## Resulting file responsibilities

- **`README.md`:** setup, support contact, and troubleshooting if needed.
- **`CONTRIBUTING.md`:** contribution process only, with a link to the README for setup.
- **`CLAUDE.md`:** repo-wide rules only. After this cleanup it may be nearly empty. Don't pad it, and don't create a new copy of setup steps in it.
- **`src/billing.js`:** the `recalcTotals()` rule in its header.
- **`src/http/client.js`:** the timeout value.

## Preventing recurrence

Before writing any fact into a doc, search for its existing home and link to it. If a value lives in code, docs should point to the file and not state the value.
