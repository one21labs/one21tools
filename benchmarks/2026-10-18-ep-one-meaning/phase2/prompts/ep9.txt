Please review this design before we start building. Team is two engineers.

Proposal: In-house Job Queue (v1)

Context: We send transactional emails (password resets, invoices, receipts). Volume today: ~200/day, projected 500/day next year. Finance requires that an invoice email is never sent twice to a customer; duplicates have caused chargeback disputes before.

Design:
- Postgres table jobs(id, type, payload, priority 1-5, status, attempts, run_at)
- Worker polls every 500ms with SELECT ... FOR UPDATE SKIP LOCKED
- Calls the email provider HTTP API; if no response within 5s, mark job failed and re-enqueue (max 5 attempts, exponential backoff)
- Plugin system so other teams can register new job types via a YAML manifest
- 5 priority levels with weighted fair scheduling
- React admin dashboard for job inspection, manual retry, and per-type throughput charts
- Estimated: 6 weeks
