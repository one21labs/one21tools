## Details

### 1. Setup steps
- The two copies contradict each other on three points:

  | | README | CONTRIBUTING |
  |---|---|---|
  | Install | `npm install` | `npm ci` |
  | Env file | copy `.env.example` | create `.env` by hand |
  | Run | `npm run dev` | `npm start` |

- The README is the right home. It is the first file a newcomer reads, and CONTRIBUTING can link to it.
- **Run command:** `npm run dev` is correct. The draft CLAUDE.md says `npm start` was replaced after a port clash. Verify against the `scripts` block in `package.json`.
- **Env file:** copying `.env.example` is correct. It can't drift from the real variables the way a hand-written `.env` can.
- **Install command (verify):** I can't settle `npm install` versus `npm ci` without the repo. If a lockfile is committed and you want reproducible installs, use `npm ci` in the README. Otherwise keep `npm install`. Pick one and write it only in the README.
- If CLAUDE.md needs the commands, it should say "see README.md#setup" and nothing more.
