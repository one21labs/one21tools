# docs-plan.md

## Principle
Each fact gets one canonical home. Every other place holds a link or nothing. History is not documented anywhere, because git is its source of truth.

## Decisions

| # | Fact | Canonical location | Other copies |
|---|------|--------------------|--------------|
| 1 | Local setup steps | `README.md` (Setup section) | Delete the copy in `CONTRIBUTING.md`. Replace it with one line: "Local setup: see README.md#setup". |
| 2 | API timeout value | `src/http/client.js` (the constant) | Delete "30 seconds" from `README.md` and "45 seconds" from `CONTRIBUTING.md`. Don't put the value in any doc. If a doc needs to mention it, say "see the timeout constant in `src/http/client.js`". |
| 3 | Support email | `README.md` | It appears only once, so no change. If `CONTRIBUTING.md` needs it later, it links to README. |
| 4 | "Call `recalcTotals()` after any mutation to line items" | A header comment at the top of `src/billing.js` | Remove it from `CLAUDE.md`. It applies to one file, so it should load when that file is opened, not in every session. |
| 5 | "Lessons learned" (2025-11 `npm start` → `npm run dev`; 2026-01 export module rename; the rest) | git history | Delete the whole section from `CLAUDE.md`. Don't move it into an ADR, a CHANGELOG, a comment, or a wiki page. |
| 6 | Env var template | `.env.example` | Setup says "copy `.env.example`" and never lists variables. |

## Details and reasoning

**Setup steps (1).** The two copies have drifted: `npm install` vs `npm ci`, copying `.env.example` vs creating `.env` by hand, and `npm run dev` vs `npm start`.
- `README.md` is the entry point for newcomers, so it owns setup.
- Its version is also the better one. The "Lessons learned" text says `npm start` was replaced by `npm run dev` after a port clash, so `CONTRIBUTING.md`'s `npm start` is stale. Copying `.env.example` also beats a hand-made `.env`.
- Before finalizing, check `package.json` for a `dev` script. Decide `npm install` vs `npm ci` once, in README. `npm ci` is usually right when a lockfile exists. This is the only fact in this plan I can't settle without seeing the repo.

**Timeout (2).** The two docs contradict each other (30 vs 45) and neither is guaranteed to match the code. Fixing one number would just create a copy that goes stale the next time the constant changes. The code is the truth, so docs should point to it and not restate it.
- Read the constant first, so you know which doc was wrong and can check nothing else relied on that number.

**`recalcTotals()` rule (4).** It is correct but misplaced. `CLAUDE.md` is always loaded, and this rule matters only inside `src/billing.js`. Write the rule once as a header comment in that file. Optionally add a one-line pointer at the `recalcTotals` definition, but don't repeat the rule there. After the move, `CLAUDE.md` has no copy.

**Lessons learned (5).** These entries are history, and git already records it. Delete the section outright.
- Check that no live rule is hiding in the narrative. The only one visible is "use `npm run dev`", which is already covered by README setup (#1). If the port clash left a real constraint, such as a fixed dev port, state it as a present-tense fact in config or README, without the story.
- Don't keep date-stamped lines or "renamed X" notes anywhere.

- **src/billing.js:** header comment with the `recalcTotals()` rule.
- **src/http/client.js:** the timeout constant, with a "source of truth" comment.
