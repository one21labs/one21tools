```markdown
# User Data Export: Implementation Tasks

Plan (approved): API endpoint that exports all of a user's data. Fast. Ship next week.

## Phase 0: Decisions (blocking; owner = PM/eng lead; target: day 1)
- [ ] D1. Data scope: list every table/store that holds user data and mark in/out
      (profile, content, logs, third-party data, derived data, deleted/soft-deleted).
      Blocks T2, T3.
- [ ] D2. Format: pick one (recommend JSON; CSV is lossy for nested data).
      Define the schema and version it. Blocks T3, T6.
- [ ] D3. Success criteria for "fast": p95 latency target and max export size.
      Decide sync vs. async (recommend async job + download link if exports can exceed ~10s).
      Blocks T4.
- [ ] D4. Authorization: who may export (self only? admins?). Re-authentication
      requirement. Blocks T1.
- [ ] D5. Sensitive fields: exclude or redact secrets, password hashes, internal
      flags, and other users' data (e.g. messages, shared content). Blocks T3.
- [ ] D6. Compliance check: does this serve GDPR/CCPA access requests? If so, confirm
      deadline and completeness requirements. Blocks T3.
- [ ] D7. Error handling and abuse limits: rate limit per user, behavior on partial
      failure, retention of generated files. Blocks T1, T4.

## Phase 1: Design (short written doc, 1 page max)
- [ ] T0. Write the design: components, data flow, API contract (request/response/errors),
      failure modes, source of truth for the field list. Link the D1-D7 answers.

## Phase 2: Build
- [ ] T1. Endpoint skeleton: route, authn/authz (D4), rate limiting (D7), error contract.
- [ ] T2. Data inventory module: one registry of exportable data sources (single source
      of truth, so new tables are added in one place).
- [ ] T3. Per-source exporters with field allow-list/redaction (D1, D5).
- [ ] T4. Assembly and delivery: streaming or paginated reads, size limits, async job
      + signed expiring download if D3 requires it.
- [ ] T5. Audit log: record who exported what and when.

## Phase 3: Verify
- [ ] T6. Tests: schema validation (D2), authz (user A cannot export user B),
      redaction (D5), empty user, large user, partial-failure behavior.
- [ ] T7. Performance test against the D3 target with a realistic large account.
- [ ] T8. Security review of the endpoint and download link handling.

## Phase 4: Release
- [ ] T9. Feature flag, staged rollout, monitoring/alerts on error rate and latency.
- [ ] T10. Docs: API reference generated from the contract (no hand-copied schema).
- [ ] T11. Rollback plan.
```
