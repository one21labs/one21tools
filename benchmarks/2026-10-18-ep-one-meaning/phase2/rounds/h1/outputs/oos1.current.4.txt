I can't open or edit your project in this session, so I haven't changed anything. Here is how I'd do it so all three places match and can't drift apart.

**Define `v4` once and have the other two read it.** Typing the literal into three files is no faster than one constant plus two imports, and it's how they end up out of sync again.

1. **Canonical definition.** Put the version in one shared spot the server owns, for example `config/api.ts` (or the equivalent in your stack):
   ```ts
   // SSoT: API version. Client config, server routes, and docs derive from this.
   export const API_VERSION = 'v4';
   export const API_PREFIX = `/api/${API_VERSION}`;
   ```
2. **Server route prefix.** Mount routes with `API_PREFIX` instead of a literal such as `'/api/v3'`.
3. **Client config.** Import `API_VERSION` or `API_PREFIX` for the base URL. If the client is a separate package that can't import server code, put the constant in a small shared module, or have the client read it from an env var that the build sets from the same constant.
4. **Docs.** Don't hand-type `v4` in the prose. Either generate the docs from the OpenAPI spec or route definitions, or use a template variable or build-step substitution that reads `API_VERSION`. If the docs are plain markdown that can't be templated, keep a single mention in one canonical doc and link to it from the others.

Before you ship, grep for leftovers such as `v3`, `/api/v`, and `apiVersion`. Check tests, fixtures, SDK examples, and the OpenAPI file too. Stale versions usually hide in those.
