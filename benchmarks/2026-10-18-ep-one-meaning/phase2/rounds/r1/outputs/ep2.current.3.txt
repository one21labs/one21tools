## Details

### 1. Setup steps

- **Canonical:** `README.md`. It is the first file a newcomer reads, and setup applies to every reader, not just contributors.
- **CONTRIBUTING.md:** delete its setup block and replace it with one line such as "Local setup: see README.md#setup". That removes the drifted copy (`npm start`, hand-made `.env`).
- **Contradictions resolved:**
  - `npm run dev` beats `npm start`. The CLAUDE.md history says dev replaced start, so CONTRIBUTING is stale.
  - `cp .env.example .env` beats "create .env by hand". The template file already is the source of truth for the variables.
  - **Verify:** `npm install` vs `npm ci`. If a lockfile is committed, `npm ci` is the better single answer. Check this and edit README once.
- **CLAUDE.md:** if it repeats setup, replace it with a pointer to README.

### 2. API timeout

- **Canonical:** the constant in `src/http/client.js`. Code is the source of truth, and the docs currently disagree (30s vs 45s), so neither number can be trusted.
- **README and CONTRIBUTING:** delete the sentence with the number. If readers need to know, replace it with a pointer ("timeout is configured in `src/http/client.js`"), not a value.
- **Verify:** read the constant before cleanup so you know which doc was wrong. The answer doesn't change the plan, but it shows how much else has drifted.

### 3. Support email

- It appears once, in `README.md`, so there is no duplication and nothing to change.
- Don't copy it into CONTRIBUTING or CLAUDE.md. Link to README instead.

### 4. `recalcTotals()` rule

- **Misplaced.** It affects only `src/billing.js`, so a root-level CLAUDE.md pays for it on every session while it applies to one file.
- **Move** it to a header comment at the top of `src/billing.js`, where it is read exactly when it is relevant. Then **delete** it from CLAUDE.md. Don't keep both copies.
- **Optional, better still:** remove the need for the rule. If line-item mutations go through one function or setter that calls `recalcTotals()` itself, the comment becomes unnecessary. Guard with a comment only if that isn't feasible.

### 5. "Lessons learned" section

- **Delete it entirely.** Git history already holds the backstory (the 2025-11 `npm start` → `npm run dev` switch, the 2026-01 module rename). Narrated incidents also go stale, and they would be a third place for setup facts to drift.
- **Don't relocate or condense it** into another doc, ADR or changelog.

  - "Use `npm run dev`" is already in README.
  - If the port clash is a live constraint (for example, a reserved port), state it once in README setup as a present-tense fact.
  - The renamed export module needs no entry. If the old name still trips people up, put a one-line note in that module's own header.
