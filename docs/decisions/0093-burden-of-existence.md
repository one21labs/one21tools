# 0093 — burden of existence

- Date: 2026-07-26
- Context: the owner supplied every frame-level subtraction this session (context rot, token cost,
  the corpus cut, delete-not-decide, the tier reshape). The agent executed and verified well
  INSIDE each frame and never asked whether the frame should exist.

## Decision
1. **Invert the default.** Anything that (a) has not fired, (b) has not been read, or (c) has no
   record DECIDING it is a REMOVAL CANDIDATE and must argue to stay. Today the reverse holds.
2. **The standing question is "what here should not exist?"** — not "what went wrong", which is an
   additive lens whose every answer is a fix to add, and so cannot produce subtraction.
3. **Recorded, not built** (owner-directed; build is #292). Building it here would repeat the
   failure ADR 0091 removed: an unrecorded mechanism shipped because it seemed obviously right.

## Why
The structural half is the fixable half. ADR 0047 requires a cited scar to ADD a rung; nothing is
required to keep one. Cite-or-silence makes "here is a scar, add a check" easy to evidence and
"this is unnecessary" hard, because absence of need is a negative claim. An agent biased toward
production therefore meets no countervailing force; inverting the default supplies one. It would
have caught this session's three finds unaided: the undecided pipe guard, 63 records with no
outcome and 21 nothing cites, and a 428k corpus no session could read.

## Rejected alternatives
- Rely on the operator noticing — the status quo being reported as failing.
- A CLAUDE.md prose line — rung 5 for a decidable requirement (ADR 0047), and the pipe-guard scar
  shows prose losing to habit.
- More retrospect steps without inverting the default — an additive remedy for an additive bias.
- Instruct the agent better — the agent does not persist between sessions; only what is written
  into the repo carries forward, so the fix must be structural, not attitudinal.

## Assumptions
- [unverifiable] WEAKEST — a standing subtraction question produces subtraction rather than
  becoming a ritual answered "nothing, looks fine". REOPEN-IF two consecutive runs return nothing
  removable and the owner then names something removable -> make the default mechanical
  (auto-list unfired guards and uncited records) instead of asked.
- [checkable] the three classes are mechanically detectable today: no deciding record, never
  fired (gate-hits/liveness), never read (no inbound cite). owner: #292. result: pending.

## Revisit triggers
- The built check lists candidates the owner rejects as obviously needed -> too aggressive; scope
  to blocking mechanisms first (ADR 0091 prong (i)).
- A frame-level subtraction is again supplied only by the owner -> the mechanism is not reaching
  the moment framing is set; move it earlier than retrospect.
