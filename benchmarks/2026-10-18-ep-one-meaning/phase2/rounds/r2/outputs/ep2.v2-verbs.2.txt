# docs-plan.md

Each fact lives in exactly one place. Every other copy is deleted or replaced by a bare reference, with no retold content.

## Rationale and details

**1. Setup steps (duplicated and contradictory)**
- README wins because it is the entry point.
- The CLAUDE.md history says `npm start` was replaced by `npm run dev`, so CONTRIBUTING's `npm start` is stale.
- Keep CONTRIBUTING's one-line pointer free of any restated commands.
- **Open question:** `npm install` (README) vs `npm ci` (CONTRIBUTING). I can't tell which is intended. Decide it once, in README only. `npm ci` is usually the better choice for a reproducible setup, but that's your call.
- "Copy `.env.example`" beats "create `.env` by hand". The example file is then the source of truth for env variables, and no doc should list them.

**2. Timeout (contradictory, and both docs are copies)**
- The code constant is the only value that actually controls behavior, so neither doc should state a number.
- Don't "fix" either doc by picking 30 or 45. That just recreates a copy that will drift again.
- If a doc must mention timeouts, name the constant and file (e.g. "see the timeout constant in `src/http/client.js`") and give no number.
- **Action:** read the constant to see which doc was wrong. That's useful to know, but it doesn't change the decision.

**3. Support email**
- Single copy, correctly placed. No action beyond not duplicating it.

**4. Billing rule (misplaced)**
- The rule only matters in one file. An always-loaded CLAUDE.md is the wrong home for it, because it costs context on every task.
- Put it at the top of `src/billing.js`, where anyone editing line items will see it.
- **Optional follow-up (code, not docs):** have the line-item mutators call `recalcTotals()` themselves. Then the rule can be deleted outright, which beats documenting it.

**5. Lessons learned (history in docs)**
- Delete the entire section. Don't move it to an ADR, CHANGELOG, wiki page or comment, and don't shorten it into another doc. git history already holds it.
- Anything in it that is still true is already stated elsewhere:
  - "Use `npm run dev`" is in README (item 1).
  - The current name of the export module is in the code.
- The port-clash story and the rename narrative are history only, so they go.

## Resulting state
- **README.md:** setup, support email, no timeout number.
- **CONTRIBUTING.md:** contribution process only, plus a pointer to README setup.
- **`src/billing.js`:** the `recalcTotals()` rule in its header.
- **`src/http/client.js`:** the timeout constant, the only place the value exists.
- **CLAUDE.md:** after removing items 4 and 5, nothing may be left. If so, don't keep it just to hold pointers. Add to it later only for rules that apply repo-wide.

## Prevention
- Before writing a fact in any doc, search for where it already lives and refer to it.
- In PR review, check whether a number, command or rule is being copied instead of referenced.
