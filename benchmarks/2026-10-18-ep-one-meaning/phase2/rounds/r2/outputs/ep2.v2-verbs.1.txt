Each fact lives in exactly one place. Every other copy is deleted or becomes a bare pointer (path or link only, with no retold content).

## Details and reasoning

**1. Setup steps (README vs CONTRIBUTING).**
- The two copies have drifted: `npm install` vs `npm ci`, `.env.example` copy vs hand-made `.env`, and `npm run dev` vs `npm start`.
- README is the right owner because it's the first file a new developer reads.
- Before finalizing, check the README steps against `package.json` scripts and `.env.example`.
  - The `npm start` → `npm run dev` switch in the lessons section suggests README is the current version.
  - If a lockfile is committed, consider changing `npm install` to `npm ci` in README, since that is the better practice. Make that change in README only.
- Result: one copy of the steps, and CONTRIBUTING has a pointer.

**2. Timeout (30s vs 45s).**
- The two docs contradict each other, and the code is the real source of truth.
- Deleting both sentences removes the contradiction and the chance of future drift.
- If a doc must mention it, write only "see `src/http/client.js`" (the constant name), never a number.
- Action item: read the constant. If readers actually need the value, put it in a code comment next to the constant.

**3. Support email.**
- It appears once, so it is not a duplicate. It stays in README.

**4. Billing rule.**
- `CLAUDE.md` is always loaded, so a rule about one file wastes context everywhere else.
- Move the rule verbatim into a header comment in `src/billing.js`: "Always call `recalcTotals()` after any mutation to line items."
- Optional follow-up: the better fix is to remove the rule entirely.
  - Make the line-item mutation functions call `recalcTotals()` internally, so no caller can forget.
  - Then delete the header comment too.
  - This is a code change, so it is separate from the docs work.

**5. Lessons learned.**
- Git history is the source of truth for history.
- The current facts from that section already live elsewhere:
  - The dev command is in README setup.
  - The export module's current name is in the code.
- The narrated story and dates are deleted outright.
- If any code or doc still uses the old export module name, fix it at that location.

## Resulting CLAUDE.md
Everything in the draft is removed or relocated. Keep CLAUDE.md only for rules that apply repo-wide and that nothing else already states. Don't pad it with pointers just to have content.
