```markdown
# User Data Export: Implementation Tasks

Plan (approved): Build an API endpoint that exports all of a user's data.
Use whatever format is easiest. Should be fast. Ship next week.

## Phase 0: Decisions (blocking, do first, ~1 day)
Each needs a one-line written answer. Record each answer once, in this
file's "Decisions" section below, and have the code and tests refer to it.

- [ ] D1. Data scope: list every table/store holding user data. Decide what
      "all" includes (profile, content, logs, third-party data, derived data)
      and what is excluded (other users' data, internal fields, secrets).
- [ ] D2. Format: pick one (JSON recommended: easiest, and it keeps nested
      data). Define the schema and version it.
- [ ] D3. Success criteria: a number for "fast" (e.g. p95 under X s for a
      typical user, and a maximum supported export size).
- [ ] D4. Sync vs async: if D3 can't be met inline for the largest users,
      decide on a background job plus a download link.
- [ ] D5. Authorization and security: who can request an export (the user
      only? admins?), re-authentication, rate limit, audit log, and link
      expiry if async.
- [ ] D6. Compliance check: confirm whether this is meant to satisfy a
      GDPR/CCPA access request, since that changes scope and deadlines.
- [ ] D7. Failure behavior: what the caller sees on timeout or partial
      failure. Never return a silently incomplete export.

## Phase 1: Build
- [ ] T1. Inventory of user-data sources, from D1, as one list in code
      (the single source of truth for what gets exported).
- [ ] T2. Export schema/serializer, from D2, one module.
- [ ] T3. Per-source collectors that read through the T1 list; stream or
      paginate so memory stays bounded.
- [ ] T4. Endpoint (e.g. GET /users/me/export): authN/authZ, rate limit,
      error contract from D7.
- [ ] T5. If D4 = async: job queue, status endpoint, expiring download link.
- [ ] T6. Audit logging of every export request.
- [ ] T7. Redaction of fields excluded in D1.

## Phase 2: Verify
- [ ] T8. Tests: a user can't export another user's data; the export
      contains every source in T1 (fails if a new source is added but not
      exported); excluded fields are absent.
- [ ] T9. Load test against D3 using a large-user fixture.
- [ ] T10. Failure test: kill a collector mid-export and confirm the
      D7 behavior.

## Phase 3: Ship
- [ ] T11. Docs for the endpoint (generated from the schema, not hand-copied).
- [ ] T12. Rollout behind a feature flag; alert on export errors/latency.
- [ ] T13. Release.
```
