- README.md keeps `clone, npm install, copy .env.example, npm run dev`.

### 2. Timeout
- Neither 30 s (README) nor 45 s (CONTRIBUTING) is trusted. Read the constant in `src/http/client.js`, which is the only authority.
- Remove the number from both docs. If a reader needs it, the docs say "see `src/http/client.js`" and carry only the path or constant name.
- Add a one-line comment at the constant saying it is the source of truth for the timeout.
- Nothing is lost: the value is one grep away, and it can no longer drift.

### 3. Support email
- It appears once, in README.md, so it is not duplicated. Keep it there.

### 4. `recalcTotals()` rule
- It applies only inside `src/billing.js`, so it belongs there. Put it as a header comment at the top of that file.
- Remove it from CLAUDE.md. That file loads in every session, and the rule costs context everywhere else.

### 5. "Lessons learned"
- Delete the whole section. It is history, and git history is the source of truth for it.
- Do not move it into an ADR, CHANGELOG, code comment or new history file.
- Both dated entries are covered:
  - `npm start` → `npm run dev` is already stated as the current command in README. The port-clash story is dropped.
  - The export-module rename is dropped. If a current rule follows from it, state only that rule, in the file it concerns.

## Resulting CLAUDE.md
- It keeps only rules that apply repo-wide.
- If it has no repo-wide rules left, keep it minimal. Do not paste setup or timeout facts into it.

## Preventing new copies
- Before writing a fact in any doc, search for its owner. If one exists, link to it.
- Source-of-truth list:
  - Setup commands → README.md
  - Timeout → `src/http/client.js`
  - Billing rule → `src/billing.js` header
  - History → git
