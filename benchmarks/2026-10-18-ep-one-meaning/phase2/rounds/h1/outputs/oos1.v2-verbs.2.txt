I can't open your project in this session, so I haven't made any edits. Here is how I'd do it.

Don't type `v4` into three files. Define it once and have the other two places read it. That takes no longer than three edits, and the next bump becomes a one-line change.

**1. One source of truth**

Put the version in one shared module or config file. The exact location depends on your layout, for example:

```ts
// config/api.ts  (source of truth for the API version)
export const API_VERSION = "v4";
export const API_PREFIX = `/api/${API_VERSION}`;
```

If the client and server are separate packages that can't import from each other, use a small shared package. A single `api-version` file that both build steps read also works.

**2. Make the three places refer to it**

- **Server route prefix:** import `API_PREFIX` and mount the router with it: `app.use(API_PREFIX, router)`. Remove the literal.
- **Client config:** import `API_VERSION` or `API_PREFIX` and build the base URL from it. Remove the literal.
- **Docs:** don't hand-write `v4`. Generate it from the source. If you have an OpenAPI spec, set `info.version` and `servers[].url` from the constant at build time. Otherwise use a template variable or a small build-step substitution. If docs are plain Markdown with no build step, keep the version in one line and have the other pages link to it instead of repeating it.

**3. Check before shipping**

Run `grep -rn "v[0-9]" --include="*.{ts,js,py,json,yaml,md}"` over the source and docs. Every remaining `v3`, `v4` or `/api/v` literal should be either the constant itself or something generated from it. Then hit one route at `/api/v4/...` from the client to confirm the prefix and the base URL agree.
