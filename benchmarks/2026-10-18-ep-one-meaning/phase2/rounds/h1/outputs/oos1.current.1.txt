I can't open or edit your project from this session, so I haven't changed anything. Here's the approach I'd take.

Don't hardcode `v4` in three places. Define it once and have the other two read it. That takes about as long as three literals, and it means the next bump is a one-line change.

1. **Pick one home for the value.** Use a shared constant or config entry, such as `API_VERSION = "v4"` in `config/api.ts` or an env/config file both sides already load.
2. **Server route prefix:** build it from the constant, e.g. `` `/api/${API_VERSION}` ``.
3. **Client config:** build the base URL from the same constant. If the client is a separate package or deploy that can't import from the server, have it read the version from the shared config or from a build-time env var.
4. **Docs:** these can't import code. Generate the version into them (a template variable, or the OpenAPI spec's `servers`/`basePath`), or have the docs point to the constant instead of restating it. If it truly has to be a literal in the docs, add a CI check that greps for the literal and fails if it differs from the constant.

Before you ship, grep for `v3`, `v1` and `/api/` across the repo. A stray hardcoded old version in tests, redirects or examples is the usual cause of a mismatch.
