## Details

**1. Setup steps (contradiction: `npm install` / `.env.example` / `npm run dev` vs `npm ci` / hand-made `.env` / `npm start`)**
- README is the canonical home because it is the first thing a newcomer reads. CONTRIBUTING gets a pointer only.
- Verify before writing the final text (this is the one thing I couldn't check):
  - Run command: `npm run dev`, since the CLAUDE.md draft says `npm start` was retired. Confirm it matches the `scripts` block in `package.json`.
  - `.env`: confirm `.env.example` exists. If so, "copy `.env.example`" is right and "create by hand" is stale.
  - `npm install` vs `npm ci`: pick one. `npm ci` is the better fit if a lockfile is committed and you want reproducible installs. `npm install` is fine otherwise. Either way the choice appears only in README.
- Where `npm start` stays valid (for example production), that belongs in the deploy docs or `package.json`, not in the dev setup.

**2. Timeout (contradiction: 30s vs 45s)**
- The code is the authority, and neither doc is guaranteed to be right. Read the constant in `src/http/client.js`.
- Delete the number from both docs. Writing the correct number into README would just recreate the duplicate and drift again.
- If a doc must mention it, write "see `<CONSTANT_NAME>` in `src/http/client.js`" with the name and path only.
- If the value ought to be configurable, that is a separate change and out of scope here.

**3. Support email**
- It appears once, in README. Nothing to reconcile today. This entry stops anyone adding a second copy to CONTRIBUTING.

**4. `recalcTotals()` rule**
- It is misplaced in CLAUDE.md. It applies to exactly one file, so it goes in `src/billing.js` as a header comment, e.g. `// Invariant: call recalcTotals() after any mutation to line items.`
- Remove it from CLAUDE.md in the same change so the rule never exists in two places.
- Optional follow-up, separate scope: remove the need for the rule by making line-item mutations go through a function that recalculates totals itself. Deleting the way to get it wrong beats documenting it.

**5. Lessons learned**
- Delete it outright. It is backstory, and git is the single source for it.
- Anything in it that is still true today is already covered elsewhere:
  - "Use `npm run dev`" is in README Setup (item 1).
  - If the port clash left a live constraint, such as the dev server needing a specific port, state that one present-tense fact in README next to the setup step or in the config that sets the port. Don't retell the incident.
- The export-module rename is only history, so it goes.

## Resulting CLAUDE.md
Only rules that apply repo-wide, and each stated once. After this change it contains nothing from items 4 and 5. It may carry a path-only pointer such as "Setup: README.md#setup".
