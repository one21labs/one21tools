# docs-plan.md

## Principle
Each fact has one canonical location. Every other copy is deleted or becomes a bare reference (path or name only, with no restated content). History lives in git, not in docs.

## Notes per item

1. **Setup.** The two copies disagree on `npm install` vs `npm ci`, on `.env.example` vs a hand-made `.env`, and on `npm run dev` vs `npm start`. The lessons-learned text says `npm start` was retired, so README's `npm run dev` is current and CONTRIBUTING's copy is the stale one. Before finalizing, check README's steps against `package.json` scripts and the existence of `.env.example`. Also decide whether `npm install` or `npm ci` is intended. `npm ci` is only right if a lockfile is committed.
2. **Timeout.** The code is the source of truth, and neither doc number can be trusted. Documenting the value would create a new copy that drifts again. Deleting the number removes the contradiction.
3. **Support email.** It appears once, so there is nothing to merge.
4. **Billing rule.** Write it once, as a present-tense rule in the `src/billing.js` header: "After any mutation to line items, call `recalcTotals()`." It is then read exactly when someone edits that file.
5. **Lessons learned.** Each entry is either history (delete) or a rule that is still true. Rules that are still true are stated once, as present-tense facts, in the file that owns them. The `npm run dev` rule is already covered by item 1, and the port-clash story is deleted. Only two entries were visible to me (the second is cut off with "..."), so review the rest of the section with the same test.

## Resulting CLAUDE.md
It keeps only rules that apply across the whole repo, plus references to canonical files. If nothing cross-cutting remains, it is a few lines long.
