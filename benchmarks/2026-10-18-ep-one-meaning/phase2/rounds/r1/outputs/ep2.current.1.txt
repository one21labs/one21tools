# docs-plan.md

Principle: each fact has one canonical home. Every other copy is deleted or becomes a pointer that carries only a path, with no restated content.

## Rationale and details

**1. Setup steps (contradictory).**
- The README version (`npm install`, copy `.env.example`, `npm run dev`) is canonical.
- The CONTRIBUTING version has drifted. It uses `npm start`, which the lessons-learned note says was replaced by `npm run dev` after the port clash. It also has people create `.env` by hand, which can drift from `.env.example`.
- `.env.example` is the single source for which env vars exist. The README only says to copy it.
- Before finalizing, check `package.json` scripts to confirm `dev` is the right command.
- Also decide `npm install` vs `npm ci`. `npm ci` is better for reproducible setups if a lockfile is committed. If you want it, change the README, which is still the only place it appears.

**2. Timeout (contradictory, and a code value duplicated into prose).**
- The constant in `src/http/client.js` is the truth. Neither doc value can be trusted, and I haven't seen the actual value.
- Don't pick 30 or 45 as the winner without reading the constant.
- Remove the number from both docs, because a doc copy of a code value will drift again.
- If readers need to know, write "see the timeout constant in `src/http/client.js`", with no number.

**3. Support email.** It appears once, so there's no duplication. Keep it in the README, since that's where users look.

**4. Billing rule (misplaced).**
- The rule only matters in `src/billing.js`, so it belongs there. Put it in a header comment, and optionally one line at the `recalcTotals()` definition.
- Loading it into `CLAUDE.md` would pay for it in every session, including ones that never touch billing.
- It must not live in both places. Delete it from `CLAUDE.md`.

**5. Lessons learned (misplaced backstory).**
- Delete the section outright. Don't move or condense it into a CHANGELOG, an ADR or a "history" doc. Git history already holds this.
- The current truth from those entries is already stated in the canonical places:
  - `npm run dev` is in the README setup.
  - Wherever the renamed export module is referenced, use its current name.
- A bare pointer such as a commit hash or issue number next to a constraint is fine. The retold story is not.

## Resulting `CLAUDE.md`
Keep only rules that apply across the whole repo. For setup, it holds a pointer ("Setup: see `README.md`") and no steps. If nothing cross-cutting remains, it can be nearly empty.
