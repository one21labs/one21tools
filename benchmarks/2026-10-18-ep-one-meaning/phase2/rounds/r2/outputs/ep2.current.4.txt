# docs-plan.md

## Principle
Each fact gets one home. Every other mention is deleted or becomes a bare path or link, with nothing restated.

## Decisions

| # | Fact | Canonical location | Other copies |
|---|------|--------------------|--------------|
| 1 | Local setup steps | `README.md` (setup section) | CONTRIBUTING's copy is **deleted** and replaced by one line: "Setup: see README.md#local-setup". |
| 2 | API timeout value | `src/http/client.js` (the constant) | The README's "30 seconds" and CONTRIBUTING's "45 seconds" are **both deleted**. No docs state a number. If readers need a pointer, write "see `src/http/client.js`" and nothing more. |
| 3 | Support email | `README.md` | It appears only once, so there is nothing to merge. It stays. |
| 4 | `recalcTotals()` rule | Header comment of `src/billing.js` | **Removed from CLAUDE.md**. The rule only matters in that one file, so it belongs next to the code it constrains. |
| 5 | "Lessons learned" (2025-11 `npm start` → `npm run dev`, 2026-01 export rename, and so on) | git history | **Deleted outright** from CLAUDE.md. It is not moved to an ADR, changelog, comment or history file. |

## Rationale and details

**1. Setup steps.**
- The README version wins because it matches the only evidence we have of what is current. The CLAUDE.md lesson says `npm start` was replaced by `npm run dev`, so CONTRIBUTING's `npm start` is stale.
- `.env.example` is also the canonical way to create the env file. CONTRIBUTING's "create .env by hand" goes away with the rest of its copy.
- **Check before applying:** confirm that `package.json` has a `dev` script. Also decide whether `npm ci` or `npm install` is the intended command. `npm ci` is the usual choice when a lockfile exists. If you choose it, change it in the README, which is the single place to edit.

**2. Timeout.**
- The README and CONTRIBUTING disagree (30 vs 45), and the code is the authority. Neither number is verified here.
- Deleting both removes the drift risk permanently. Correcting one of them would just recreate the problem the next time the constant changes.
- **Check before applying:** read the constant in `src/http/client.js`. If either doc turns out to be right, it is still deleted, because the doc copy has no value over the code.

**3. Support email.** It has one occurrence and one audience (people reading the README), so no action is needed.

**4. Billing rule.**
- CLAUDE.md is loaded for every task, so a rule that applies to one file is a recurring cost everywhere else.
- Put it as a header comment in `src/billing.js`, for example: "Always call `recalcTotals()` after any mutation to line items."
- Optional follow-up, not part of this restructure: if `recalcTotals()` can be called automatically from the mutators, the rule disappears entirely. That is better than documenting it.

**5. Lessons learned.**
- Git history already holds the backstory, so a narrated copy in CLAUDE.md is a second, drifting source.
- The only still-true fact in that section is "use `npm run dev`". It already lives in the README setup, so nothing needs to be carried over.
- No commit-hash or issue pointers are needed. Add one only if you want a bare cite next to a live constraint.

## Resulting state
- **README.md:** setup steps, support email. No timeout number.
- **CONTRIBUTING.md:** contribution process only, plus a link to the README setup. No setup steps and no timeout number.
- **CLAUDE.md:** nothing remains from this draft. Either drop it or keep it for genuinely project-wide rules only. It should not restate setup. At most it carries a pointer to `README.md`.
- **src/billing.js:** gains the `recalcTotals()` header comment.
- **src/http/client.js:** unchanged. It is the authority for the timeout.
