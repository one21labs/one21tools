================ DOCTRINE REVIEW ================
I'll review the doctrine against the surrounding skill text and related principles, not the wording.**DEFECTS**

1. **Subtractive-default amputates intentional surfaces.** When the hazard is a required capability (publish PR, edit budgeted doc, run a gate), the correct fix is often a control. “Delete what made it possible / only add in the rare case” steers the agent to remove the capability or leave the class unfixed rather than ship the first necessary guard. Process-Level Poka-yoke in the same file already requires additive process guards; the new default does not carve that out.

2. **“Nothing can be removed” and “the loss is real” are not checkable.** Any agent can claim elimination was impossible (or always possible by deleting the feature). There is no scar, counterexample, or acceptance test that shows the additive branch was wrongly taken or wrongly refused.

3. **The BAR drops latent control failures.** Classes that matter here and are not yet a wrong product answer or a demonstrated false green: gate with no decision-logic test; wired guard that never fires on part of its surface (ADR 0086 class); undeclared / unwatched surface; missing canary; defense-in-depth backstop removed while the primary still “works.” “Could produce” does not operationalize these—agents treat them as hygiene.

4. **The BAR drops false reds and trust failures.** Same file: false blocks train bypass. A deny that blocks legitimate work does not produce a wrong answer for the recipient and is not a false green. Under the BAR it is “logged and left alone,” so the loop optimizes for green product/gate outcomes while teaching operators to ignore guards.

5. **The BAR drops non-answer defects the rest of the system treats as load-bearing.** Token/context waste, cost, provenance/disclosure, missing `xfam` / FRAME-UNCHECKED, scope-drift that fakes a quiet tail, pure SSoT restatement, dead process surface that never touches the recipient’s answer. Sweep’s own lanes (staleness, dead refs, contract drift, loop/tooling) will surface these; the BAR then discards them as non-findings, so empty `ids` can mean “bar filtered,” not “clean.”

6. **Below-bar items have no log home and never enter the quiet-tail predicate.** “Logged and left alone” is not in the round-line schema and does not affect `sweep-state.mjs`. Convergence is defined on counting findings while the bar redefines what counts—without a residual ledger, the backlog can grow forever under a CLEAN verdict.

7. **Rung 0 is on the wrong ladder.** The section is still a detection-latency ladder ranked by “how early they catch.” Eliminate does not catch; it removes the hazard. That is hierarchy-of-controls rank 0, not an earlier detector. Framing 0 as “earlier/stronger catch” is false for every rung definition that follows.

8. **“Rungs 1–5 all guard a surviving hazard” is false for rung 5 (and strained for 1).** Rung 5 is the designated home for undecidable judgment, not a residual control on a hazard that failed elimination. Rung 1’s “error cannot happen” is a blocking control on a still-present action surface, not the same kind of thing as 2–4 detection—but calling 5 a guard-on-surviving-hazard misstates executable-home doctrine in the same section.

9. **“Try rung 0 first” overrides the economics clause without a bound.** Eliminate can be a redesign or capability cut; a cheap later rung may fully catch the defect. The text requires attempting 0 first, then “cheapest,” with no rule for when eliminate’s cost or value-loss makes it the wrong first move—so either agents skip 0 silently or they over-eliminate.

10. **Same-file contradiction: subtractive poka-yoke vs Process-Level Poka-yoke.** Immediately below, doctrine still mandates gates-on-gates, knowledge-base guards, and “watch the watchers.” That stack is additive by design. No rule says which doctrine wins when a sweep would delete a process guard that Process-Level requires.

11. **Same-file contradiction: “earlier is stronger” + multi-rung backstops.** Choosing-the-rung now prefers single earliest (0, else cheapest), while “full coverage deletes the mirror” still allows a later CI backstop, and Process-Level / ADRs in this repo keep layered rungs (e.g. prevent + post-edit + CI). Doctrine simultaneously wants one cheap home and stacked controls.

12. **Same-skill contradiction: stop condition.** Frontmatter/intro still stop on “nothing new” / finding rate zero; the BAR stops on “nothing that matters,” with below-bar noise allowed every round. Those are different fixed points. Script and prose will disagree on what a quiet round means.

13. **Same-skill contradiction: additive justification vs round-line schema.** Fix step requires saying why an additive ship is justified “in the round line”; the prescribed JSON is only `round`, `ids`, `xfam`. The rule cannot be followed as written and cannot be audited from the log.

14. **Unfalsifiable BAR.** “Could produce a wrong answer for the person receiving the work” is a counterfactual with no required demonstration path, no severity floor, and no independent check. Two reviewers can classify the same defect opposite ways with no way to show either broke the rule.

15. **Unfalsifiable rarity / subtractive default.** “Additive only in the rare case,” “mostly SUBTRACTIVE,” and “try rung 0 first” (with silent reject of 0) cannot be failed by observation: there is no rate, no required reject-record on the ladder, and “mostly” has no threshold. Only the unimplemented “say why in the round line” was checkable, and the schema omits it.
