# docs-plan.md

## Principle
Each fact is defined in one place, and every other place refers to it by path or link without restating it. History lives in git and is not kept in docs.

## Details

**1. Setup.** The two copies contradict each other. The README version (`npm install`, copy `.env.example`, `npm run dev`) matches the draft's own history note that `npm start` was replaced by `npm run dev`. The `CONTRIBUTING.md` version (`npm start`, create `.env` by hand) is the stale one, so it is deleted and not merged. The commands themselves are defined by `package.json` scripts, so the README refers to script names and does not describe what they do.

**2. Timeout.** Neither 30 nor 45 can be trusted until someone reads the constant. A hand-maintained number in prose will drift again, so the root cause is that the value was written in docs at all. The fix removes the copies and adds no guard.

**4. `recalcTotals()`.** Put the rule in the header comment of `src/billing.js`. A better fix removes the rule: have the line-item mutation functions call `recalcTotals()` themselves, so callers can't forget it. Removing the step beats documenting or guarding it. If you do that, the comment shrinks to one line or goes away.

**5. Lessons learned.** Delete every dated entry. What is still true today is already stated once elsewhere: `npm run dev` is in the README, and the current export module name is in the code. If the port clash is a live constraint, such as a required port, state it once as a present-tense fact in the README setup section, without the story.

## Resulting `CLAUDE.md`
After items 4 and 5 it has no content, so don't create it with filler. If you later add repo-wide rules, put only those in it. Any rule that applies to one file goes in that file's header.
