I can't open your project in this session, so I haven't changed any files. Here is the approach I'd take.

Don't paste `v4` into three files. Define it once and have the other three read it. That's one constant plus two imports, so it's no slower than three edits, and the three can't drift apart again.

1. **Source of truth:** add `API_VERSION = "v4"` to one shared config module or file. Put a comment on it saying it's the source of truth. If the client and server are in different languages or packages, use a small `api-version` file or JSON that both read.
2. **Server:** build the route prefix from the constant, e.g. `` `/api/${API_VERSION}` ``, in place of a literal.
3. **Client config:** build the base URL from the same constant.
4. **Docs:** generate the version string from the constant at build time (a template variable or a small substitution step), or have the docs refer to the config file by path. Don't hand-type `v4` in the docs.

Before editing, search for every existing `v3`, `v4` or `/api/v` literal, not only the three places you named. A stray copy in tests, an OpenAPI spec or a CI script will break after the change.
