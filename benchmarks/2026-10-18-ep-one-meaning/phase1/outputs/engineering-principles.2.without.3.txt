# docs-plan.md: where each fact lives

## Principle
Each fact has one home. Every other mention is deleted or becomes a pointer to that home. Facts the code already defines live in the code. History lives in git.

## 1. Local setup steps
- **Canonical location:** `README.md`, in the setup section.
- **CONTRIBUTING.md:** Delete its copy of the steps. Replace it with one line, "Local setup: see README.md#setup".
- **CLAUDE.md:** Don't add a copy. If the file needs a setup pointer, use the same one-line link.
- **Why README wins:** `npm run dev` is the current command. The "Lessons learned" entry confirms `npm start` was retired after the port clash. So the CONTRIBUTING copy (`npm ci`, hand-made `.env`, `npm start`) is the stale one.
- **One check before deleting:** Confirm README's `npm install` is what you want. If contributors should get lockfile-exact installs, change README to `npm ci` in the one canonical place. Don't keep both variants.

## 2. API request timeout
- **Canonical location:** the constant in `src/http/client.js`. It is the only source of truth.
- **README.md:** Delete "API requests time out after 30 seconds". If readers need to know, replace it with "see the timeout constant in `src/http/client.js`", with no number.
- **CONTRIBUTING.md:** Delete "45 seconds" the same way.
- **Why:** The two docs contradict each other, and a number in prose will drift again. Read the constant to find out which doc was right. That is only worth doing if you want to know whether anyone has been misled. Neither number needs to survive.

## 3. Support email
- **Canonical location:** `README.md`. It is the only copy, so nothing is duplicated.
- **CONTRIBUTING.md:** If it needs a contact, link to the README. Don't repeat the address.

## 4. `recalcTotals()` rule
- **Canonical location:** a comment at the top of `src/billing.js`, or next to the line-item mutation code. It would read: "After any mutation to line items, call `recalcTotals()`."
- **CLAUDE.md:** Delete the rule from the root file.
- **Why:** The rule applies to one file. A comment there is seen by every human and agent who edits it. Root-level CLAUDE.md should hold only repo-wide guidance.
- **Optional:** If mistakes keep happening, route all mutations through one helper that calls `recalcTotals()` itself. Then the rule can't be broken and the comment can go.

## 5. "Lessons learned" section in CLAUDE.md
- **Canonical location:** none. Delete the whole section.
- **Dated narrative** ("2025-11: we originally used npm start…", "2026-01: renamed the export module…"): This is history, and git log and commit messages already hold it. In CLAUDE.md it only adds noise and goes out of date.
- **The surviving fact in the npm entry:** "use `npm run dev`" is already in README (item 1). If you want the reason kept, add a short clause there, for example "(dev uses a different port than the old `npm start`)".
- **The export-module rename:** Delete it. If the old name still matters, put a deprecation note at the module itself. Don't put one in CLAUDE.md.

## Resulting structure
- **README.md:** setup, support email, and a pointer to `src/http/client.js` for the timeout.
- **CONTRIBUTING.md:** contribution process only, with pointers to README for setup and contact.
- **CLAUDE.md:** short. It holds only repo-wide guidance that can't be found in code or README. If nothing like that remains, it can be a few lines or dropped.
- **`src/billing.js`:** the `recalcTotals()` rule as a comment.
- **`src/http/client.js`:** the timeout, as before.
