I can't open or edit your project in this session, so I can't make the change myself. Here is how I'd do it.

**Define `v4` once and have all three places read it.** Writing the literal into three files is the same work as one constant plus three references. It's also how they drifted apart in the first place.

**1. One definition.** Put it in the file your server and client already share, or in a small config file if they share nothing:

```ts
// config/api.ts  (SSoT for the API version)
export const API_VERSION = "v4";
```

If the client and server are separate packages, use a repo-root `api-version.json` (`{ "version": "v4" }`) that both import. That is still one definition.

**2. Three consumers.**
- **Server route prefix:** `app.use(`/${API_VERSION}`, router)`, replacing the hardcoded `"/v3"` or whatever is there now.
- **Client config:** `baseURL: `${HOST}/${API_VERSION}``.
- **Docs:** don't type `v4` by hand. Generate the docs from the OpenAPI spec, or substitute the value in a docs build step, for example a `{{API_VERSION}}` placeholder filled in from the same constant. If a placeholder isn't practical before you ship, hardcode `v4` in the docs only. Leave a comment pointing at `config/api.ts` and add a CI grep that fails if the docs version differs from the constant.

**3. Check for leftovers before shipping.** Search for the old version string (`grep -rn "v3"`, adjusted to whatever it was) across code, tests, fixtures, OpenAPI specs, and CI or deploy configs. Other copies of the version are likely, and any that remain will break the match you want.
