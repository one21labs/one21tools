```markdown
# Config Subsystem: Completion Plan

## Goal
Read config.json at startup and validate three fields: api_url, team_id, log_level.
This is the only requirement, and it comes from the one team that uses the tool.

## Status
| Component | State | Requested by anyone? |
|-----------|-------|----------------------|
| JSON adapter | Done | Yes |
| Startup load + validation of 3 fields | Not confirmed done | Yes |
| YAML / TOML / XML adapters | Scaffolded | No |
| Hot-reload watcher | Half wired | No |
| Schema-migration framework | Interfaces only | No |

## Phase 1: Ship the requirement (this sprint, blocking)
1. Define the schema for the 3 fields in one place (SSoT): type, required/optional,
   allowed values (e.g. log_level enum), and url format for api_url.
2. Wire the JSON adapter to startup: load config.json, validate, fail fast with a
   message naming the bad field and the expected value.
3. Decide and document: missing file, malformed JSON, unknown extra keys,
   and defaults (if any).
4. Tests: valid config; each field missing; each field invalid; malformed file;
   missing file.
5. Confirm with the consuming team using a real config.json from them.
Exit criteria: the consuming team's actual config loads and an invalid one is
rejected with a clear error.

## Phase 2: Finish the unrequested components (gated)
Gate: start a component only when (a) Phase 1 is shipped, and (b) a named user or
team has asked for it, or the team consciously decides to fund it as speculative work.
Each item below needs a one-paragraph design (success criteria, error handling,
failure modes) before implementation.

### 2a. YAML / TOML / XML adapters (each independent)
- Implement parse -> common config model; reuse the Phase 1 validator (no per-format
  validation).
- Shared adapter contract test suite run against every adapter.
- Format selection: by file extension; define behavior for ambiguous/missing ext.
- Cost driver: XML (attributes vs elements mapping has no obvious canonical form).
  Do last, or cut.

### 2b. Hot-reload watcher
- Open design questions before wiring: what is reloaded (all fields or only
  log_level?), what happens when the new file is invalid (keep last good config),
  how consumers are notified, debounce for partial writes, platform differences.
- Note: api_url and team_id changing at runtime is probably unsafe for a CLI tool.
  Decide per field.

### 2c. Schema-migration framework
- Requires a second schema version to exist. With one version there is nothing to
  migrate, so there is nothing to test against.
- Gate on an actual breaking change to the config shape. Implement the first
  migration alongside that change, not before it.

## Risks
- Every unrequested component is code that must be maintained, tested, and
  documented, and has no user to catch its bugs.
- Unvalidated assumptions in 2a-2c about how the tool will be used.

## Open questions
- Does anyone expect another format, reload, or migration? Who, and by when?
- Is the architecture itself (pluggable adapters) worth keeping as-is while only
  JSON is used?
```

**Why I sequenced it this way:**

- **The sprint goal is the requirement.** Everything the team needs is JSON plus three-field validation, so that has to ship first. I couldn't tell from your description whether the startup wiring and validation are finished. The adapter being done isn't the same thing.
- **The two weeks are spent either way.** Finishing the adapters, watcher and migrations won't recover that time. It adds more unrequested code that needs tests and maintenance. The watcher and migrations also need design decisions no one has made yet. With a single schema version, a migration framework has nothing to run against.
- **The scaffolding isn't lost.** The adapter interfaces and half-wired watcher stay in the repo, and Phase 2 can pick them up as soon as someone asks.

If you still want all three finished this sprint, the Phase 2 items can be made unconditional. Even then I'd keep Phase 1 first and write the short design for the watcher and migrations before building them.
