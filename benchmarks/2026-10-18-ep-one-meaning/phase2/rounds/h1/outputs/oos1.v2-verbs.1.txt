I can't open your project in this session, so I haven't made any edits. Here is how I'd do it so the three places can't drift apart again.

**Define `v4` once and have the other three refer to it.** One constant plus three references is no slower than three literals, and it won't need fixing the next time the version changes.

1. **Source of truth:** one shared constant, e.g. `API_VERSION = "v4"` in your existing constants or config module. Add a comment there saying it is the source of truth.
2. **Server route prefix:** build it from the constant, e.g. `` `/${API_VERSION}` ``, in place of the literal.
3. **Client config:** build the base URL from the same constant. If the client is a separate package that can't import the server's module, put the constant in a shared package. Alternatively, make the server the source of truth and have the client read it at build time.
4. **Docs:** don't type `v4` by hand. Generate the version string from the constant (a template variable, or your OpenAPI or docs build step), or have the docs say "see `API_VERSION` in `<path>`".
5. **Guard against drift:** add a small test or CI check that fails if a literal `/v\d+` appears outside the constant's file. This is optional.

I'd skip any extras you'd be tempted to add while you're in there, such as keeping v3 routes alive, a deprecation path, or a changelog. Those are separate work, and none of them is needed to make the three places match.
